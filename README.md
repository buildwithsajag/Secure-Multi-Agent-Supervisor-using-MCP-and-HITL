# Himalayan Voyager AI

A multi-agent travel planner built with FastAPI, LangGraph, Groq, MCP, PostgreSQL, and a browser-based interface. Enter a trip request to receive flight, hotel, weather, budget, and itinerary guidance. The graph pauses for human review before producing the final plan.

Create a local `.env` file in the project root for credentials. Do not commit it. Python virtual environments and generated bytecode are local files and are not part of the application source tree.

## Prerequisites

- Python 3.11 or newer
- A PostgreSQL database reachable from this machine
- A Groq API key
- Optional service keys for live hotel, flight, and weather information
- `uv`/`uvx` for the AviationStack MCP server if using live flight tools

The application requires `GROQ_API_KEY` and `DATABASE_URL` to start. The external service credentials enable their corresponding live integrations; without working credentials or network access, those integrations may be unavailable.

## Configure

1. Create `.env` in the project root.
2. Add the required values and any optional MCP service keys:

	```dotenv
	GROQ_API_KEY=your_groq_api_key
	DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DATABASE?sslmode=require

	TAVILY_API_KEY=your_tavily_api_key
	AVIATIONSTACK_API_KEY=your_aviationstack_api_key
	OPENWEATHER_API_KEY=your_openweather_api_key
	```

	The project adds `sslmode=require` to `DATABASE_URL` when it is missing. Use a PostgreSQL connection URL appropriate for your provider and environment.
3. If you want the AviationStack MCP integration, install `uv` so `uvx` is available on `PATH`:

	```bash
	python -m pip install uv
	```

## Run Locally

From the project root:

1. Create and activate a virtual environment:

	```bash
	python3 -m venv .venv
	source .venv/bin/activate
	```

	On Windows PowerShell, activate it with `.venv\Scripts\Activate.ps1`.
2. Install the dependencies:

	```bash
	python -m pip install --upgrade pip
	python -m pip install -r requirements.txt
	```
3. Confirm `.env` has the required Groq and PostgreSQL settings.
4. Start the application:

	```bash
	python app.py
	```

	Alternatively, start it through Uvicorn:

	```bash
	uvicorn app:app --host 127.0.0.1 --port 8000 --reload
	```

5. Open [http://127.0.0.1:8000](http://127.0.0.1:8000) in a browser. Check [http://127.0.0.1:8000/health](http://127.0.0.1:8000/health) to confirm the API is responding.

## Use the Planner

1. Enter a request with a destination and useful details such as origin, duration, budget, or travel preferences. The quick-prompt buttons can also fill in examples.
2. Select **Generate Draft**. The browser reads the `/plan/stream` Server-Sent Events response and appends progress as graph nodes complete.
3. Review the draft itinerary when the workflow pauses for human approval.
4. Select **Approve & Generate Final** to accept the draft, or enter feedback and select **Revise Using Feedback**.
5. Copy or download the resulting plan using the result controls.

The app keeps a thread ID in browser local storage so the approval request can resume the correct graph execution.

## API Endpoints

- `GET /`: serves the planner interface.
- `GET /health`: returns a basic health response.
- `POST /plan/stream`: streams graph node updates and the final draft as `text/event-stream`. Send JSON such as `{"message":"Plan a 5-day trip to Japan from Nepal under $1500"}`. Use `curl -N` to inspect the streaming response:

  ```bash
  curl -N http://127.0.0.1:8000/plan/stream \
	 -H 'Content-Type: application/json' \
	 -d '{"message":"Plan a 5-day trip to Japan from Nepal under $1500"}'
  ```

- `POST /api/travel`: non-streaming version of the initial travel-planning request.
- `POST /api/travel/approve`: resumes a paused graph. Send `thread_id`, `approved` (boolean), and `feedback` (required when `approved` is false).

## Run with Docker

With Docker installed and `.env` configured in the project root:

```bash
docker build -t himalayan-voyager-ai .
docker run --rm --env-file .env -p 8000:8000 himalayan-voyager-ai
```

Then open [http://127.0.0.1:8000](http://127.0.0.1:8000). The container must be able to reach the configured PostgreSQL database and external API services.

The current Dockerfile does not install `uv`/`uvx`. To use live AviationStack tools in the container, add `uv` to the image or otherwise make `uvx` available on its `PATH`.

## Troubleshooting

- **Missing `GROQ_API_KEY` or `DATABASE_URL`:** add the variable to the project-root `.env` and restart the application.
- **Database connection fails:** verify the URL, database availability, network access, and required SSL configuration.
- **A live agent has no results:** check the relevant API key, service quota, network access, and (for flights) that `uvx` can launch `aviationstack-mcp`.
- **Browser receives a stream error:** check the application terminal for the backend exception and confirm the server is reachable at the URL shown above.
- **Groq rate limits:** the shared prompt limiter reduces each model request before sending it, but it cannot guarantee a specific token count because tokenization varies by content.
